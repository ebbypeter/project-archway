# 1. Store technology metadata as properties, not tags

Date: 2026-08-30

## Status

Accepted

## Context

Technology facts (runtime, database, hosting, versions) could be modelled as
tags (e.g. `DotNet10`) or as properties. Tags used this way explode into an
unmanageable vocabulary and duplicate information that belongs in one place.

## Decision

Store all technology metadata in Structurizr `properties`. Tags are reserved
for classifications from the approved list (EnterpriseSystem, CriticalSystem,
Platform, VendorHosted, SaaS).

## Consequences

* Inventory reports (systems by runtime/database/hosting) are generated by
  querying properties.
* The validation pipeline rejects unapproved tags.
* Styling is driven by classification tags only.
