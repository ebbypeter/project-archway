== Approved Tags

Tags are classifications, never technology versions. Technology metadata belongs in
`properties` (see the modelling standards). The validation pipeline rejects any
software system tag not listed below.

=== Portfolio categories

Every enterprise system belongs to exactly one portfolio category. The category
is declared *twice* in the system file — as a `group` (which draws the boundary
on diagrams) and as a tag (which lets views filter on it, because Structurizr
has no `element.group==` view expression). `make new-system` writes both from a
single answer, so authors state it once.

* Critical Apps — orange
* Market Apps — blue
* Enterprise Apps — green
* External Apps — grey

The portfolio determines the *fill colour* of the element on every diagram
(see `models/shared/styles/element-styles.dsl`).

=== Classification tags

Classifications style the *border*, never the fill, so they compose with any
portfolio colour: `CriticalSystem` draws a thick outline, `VendorHosted` a
dashed one.

* EnterpriseSystem
* CriticalSystem
* Platform
* VendorHosted
* SaaS

To propose a new tag or category, raise a merge request against this file.
Changes require Architecture Practice approval (see CODEOWNERS).
