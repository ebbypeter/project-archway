= Repository Structure

[cols="1,2"]
|===
| `models/model.dsl` | Canonical include manifest — every model fragment is listed here, in dependency order. Pipeline-enforced.
| `models/enterprise/people/` | Canonical person definitions, one file per business domain.
| `models/enterprise/systems/<Name>/` | One folder per enterprise system: `system.dsl` + `docs/` (AsciiDoc).
| `models/integrations/<A-B>/` | First-class integration assets: `relationship.dsl`, `docs/interface.adoc`, `adr/`.
| `models/solutions/<Name>/` | Solution architectures: `architecture/*.dsl`, `docs/`, `adr/`.
| `models/shared/` | Approved tags and shared styles. Architecture Practice owned.
| `workspaces/<Audience>/` | Consumer-facing workspaces (Enterprise, Technology, Security, Integration). Views only — never definitions.
| `docs/` | Practice standards, capabilities, policies.
| `templates/` | Copy-paste starting points for new systems, integrations and ADRs.
| `scripts/` + `Makefile` | Validation, reporting and site build. CI is a thin wrapper over these.
|===

== Golden rules

. Systems and people are defined *once*, under `models/enterprise/`.
. System-to-system relationships live *only* in `models/integrations/`.
. Workspaces consume the model; they never define elements.
. Every new `.dsl` fragment is registered in `models/model.dsl`.
