# Scale Limits

Measured on a synthetic 300-system, 1000-integration estate. These numbers
drive several conventions in this repository, so they are recorded rather than
remembered.

## What scales fine

| Operation | Result | Note |
|---|---|---|
| DSL compile of 300 systems + 1000 integrations | 1.4 s | Never the bottleneck |
| 300 per-system context views | ~4 min, 26 KB each | Acceptable; cache in CI |
| Distributed `group` blocks across 300 files | works | Merge into one group by name |
| `!identifiers hierarchical` at 300 systems | works | Adopt before scale, not after |

## The hard limit: view size

A landscape view degrades catastrophically with element count.

| Elements | SVG size | Width | Render |
|---|---|---|---|
| 45 | 136 KB | 3,616 px | fast |
| 60 | 188 KB | 3,588 px | ~10 s |
| 195 | 1.2 MB | 64,882 px | 154 s — unreadable |
| 300 | 2.8 MB | 65,124 px | build stalls, never completes |

**Rule: keep any single view under ~60 elements.** Past that the diagram is a
multi-thousand-pixel strip nobody can read, and the build time stops being
linear.

Consequences for this repository:

1. There is no whole-estate landscape at scale. Landscapes are scoped per
   portfolio category, generated by `scripts/generate_views.py` together with
   a portal page for each.
2. A portfolio landscape also draws the systems in other portfolios that its
   systems connect to, and those count towards the limit. A category whose
   landscape exceeds 60 systems must be split into sub-categories. `make views`
   warns when one does.
3. Per-system context views stay small naturally (a system's direct
   dependencies), so they scale to any estate size.

> **Note:** The synthetic model distributed relationships randomly, so intra-category
> connectivity was sparser than a real estate — which produces unusually wide,
> flat layouts. A real estate clusters more, so the exact pixel widths will
> differ. The ordering and the existence of a cliff will not.

## Why the category is both a group and a tag

Structurizr has no `element.group==` view expression (verified against
structurizr-java 5.0.2), so a view cannot filter by group. The portfolio
category is therefore declared twice: as a `group` for the diagram boundary,
and as a tag so views can scope to it. `make new-system` writes both from one
answer, so authors state it once.
